State matrix harness. This is not the product. It boots the real renderer against a synthetic snapshot in which the tmux session name is the state, so every pit bay holds exactly one state. Bays read active, complete, error, idle, permission, thinking. The active and thinking bays show Clear because those states live in the route pool; their cars are on the track. Every car wears its state glyph badge, drawn by styles.css: check the four pit bays read ✓, ×, ‖ and ! distinctly. Before that badge shipped, all four bays were identical.

Why no unknown bay. The two snapshot validators cover different vocabularies and neither covers all seven states. Fixtures go through normalizeSnapshot, whose FIXTURE_STATUSES omits unknown; live and imported snapshots go through normalizeImportedSnapshot, whose combination allowlist has no error or complete entry. Rendering all seven at once would need two dashboards on one page. It is not needed: stateClass() emits state-unknown uniformly and --state-bg/--state-ink are already defined for it, so any token-driven encoding covers it by construction.
